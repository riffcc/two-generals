\begin{theorem}[Safety --- Unconditional]
\label{thm:safety}
No execution of the protocol results in asymmetric decisions. \textbf{This holds for all adversary behaviors, including total channel failure (NoChannel).}
\end{theorem}

\begin{proof}
The attack key is a tripartite construction requiring:
\begin{enumerate}
    \item Virtual artifact $V$ (requires $D_A \land D_B$)
    \item Alice's response (requires $V$ and Alice having $D_B$)
    \item Bob's response (requires $V$ and Bob having $D_A$)
\end{enumerate}

The attack key exists if and only if \emph{all three} components exist. By case analysis on any Boolean combination of $(d_a, d_b, a\_responds, b\_responds)$:
\begin{itemize}
    \item If $d_a \land d_b \land a\_responds \land b\_responds$: attack key exists $\Rightarrow$ both $\Attack$
    \item Otherwise: attack key is $\mathsf{none}$ $\Rightarrow$ both $\Abort$
\end{itemize}

There is no Boolean assignment where exactly one party can attack. The Lean 4 theorem \texttt{gray\_unreliable\_always\_symmetric} proves this by exhaustive case analysis over all $2^4$ terminal states, with \emph{no fair-lossy assumption}---it classifies the \emph{terminal} state of an execution (\texttt{LocalDetect.lean}; the formalization explicitly parks timed/deadline behavior in a separate ``Timing Question'' section). Bounded-deadline reliability is the subject of Theorem~\ref{thm:liveness}. This is one of three exhaustive symmetry analyses in the formalization at complementary granularities: $2^4$ terminal attack-key states here, $2^6$ delivery states (\texttt{Exhaustive.lean}), and $2^8$ channel-state combinations for the no-pivotal-message property; each establishes symmetry over its own state space.

\textbf{Critical:} This is pure case analysis on the attack key structure. The channel model is irrelevant to safety---even under NoChannel (total message loss), outcomes are symmetric (both abort).
\end{proof}

\begin{theorem}[Liveness]
\label{thm:liveness}
Under fair-lossy channels with delivery probability $p > 0$, the probability that both parties reach a coordinated decision approaches 1.
\end{theorem}

\begin{proof}
The protocol uses six packets: $C_A, C_B$ (commitments), $D_A, D_B$ (double proofs), $T_A, T_B$ (triple proofs). Each phase requires delivery of one message type. With continuous flooding:
\begin{itemize}
    \item Phase 1: $\Pr[\text{both receive } C] = 1$ (fair-lossy)
    \item Phase 2: $\Pr[\text{both receive } D] = 1$ (fair-lossy)
    \item Phase 3: $\Pr[\text{both receive } T] = 1$ (fair-lossy)
\end{itemize}

The probability of completing all phases is $1$ under fair-lossy conditions. The attack key emerges when both parties have received $T$ (which embeds $D$, which embeds $C$).

With finite deadline $\tau$ and per-message delivery probability $p$, the probability of completing within $\tau$ is:
\[
\Pr[\text{complete}] = 1 - (1-p)^{n}
\]
where $n$ is the number of transmission attempts. For continuous flooding at rate $r$ messages/second over duration $\tau$:
\[
\Pr[\text{complete}] = 1 - (1-p)^{r\tau}
\]

With $p = 0.01$, $r = 1000$, $\tau = 10$s: $\Pr[\text{complete}] > 1 - 10^{-1565}$.
\end{proof}

\begin{remark}[Physical Interpretation of $10^{-1565}$]
\label{rmk:physical}
A failure probability of $10^{-1565}$ is so fantastically small that \textbf{you would need to run this protocol once per picosecond, on every atom in a trillion universes, from the Big Bang until the heat death of the cosmos, and you still would not expect to see a single failure}. For context: there are approximately $10^{80}$ atoms in the observable universe. The probability $10^{-1565}$ is $10^{1485}$ times smaller than one divided by that count. This is not a probability in any meaningful physical sense---it is a formality. The protocol \emph{cannot} fail by random chance; it can only fail through implementation defects, hardware errors, or environmental pathologies not captured by the fair-lossy model.
\end{remark}

\begin{theorem}[Validity]
\label{thm:validity}
If both parties intend to attack and the network is fair-lossy, both decide $\Attack$.
\end{theorem}

\begin{proof}
Both parties begin by flooding commitments. Under fair-lossy conditions, both eventually receive the counterparty's commitment, construct double proofs, exchange those, then construct triple proofs. When both have $T_A$ and $T_B$, the attack key emerges and both decide $\Attack$.
\end{proof}

\subsection{The Timed Regime: Bounded Deadlines and the Adversary Window}
\label{sec:timed-regime}

Theorems~\ref{thm:safety}--\ref{thm:validity} classify the \emph{terminal} state of an execution: the attack key either emerges (both attack) or does not (both abort), and no terminal state is asymmetric. This is the regime the Lean formalization inhabits (\texttt{gray\_unreliable\_always\_symmetric} in \texttt{LocalDetect.lean}, which the formalization itself labels a terminal-state classification). It says nothing about \emph{when} a party decides.

Real deployments impose a deadline (``dawn''): each party must commit to attack or abort at a fixed time, from its own local state, with messages still in flight. In this \emph{timed regime} a failure mode appears that has no terminal-state analogue---one party may have crossed the construction threshold before dawn while the other has not, purely because the last observation it needs is still in transit. This is the bounded-deadline $\varepsilon$, the price of replacing ``eventual'' (Theorem~\ref{thm:liveness}) with ``by dawn.''

\paragraph{The shape of $\varepsilon(\tau)$.}

We measure asymmetry probability against the deadline $\tau$ (in simulation ticks) over 1000 seeded runs per condition, using the reference Python implementation with each party deciding from local state at its own dawn and an oblivious (i.i.d.\ loss) adversary. Figure~\ref{fig:eps-tau} shows the result. The curve is not a monotone decay but a \emph{window}:
\begin{itemize}
    \item For $\tau$ well below the median completion time, neither party has finished: both abort, $\varepsilon = 0$ (symmetric).
    \item At the knife-edge ($\tau \approx$ median completion), a large fraction of runs terminate with exactly one party attacking: $\varepsilon$ peaks in the $30$--$50\%$ range, highest where the completion-time distribution is tightest. Higher loss lowers and broadens the peak.
    \item For $\tau$ well above median completion, both finish: $\varepsilon$ decays to zero. This right tail is the $(1-p)^{r\tau}$ bound of Theorem~\ref{thm:liveness}---the $10^{-1565}$ figure of Remark~\ref{rmk:physical} corresponds to operating deep in this tail.
\end{itemize}
Higher loss shifts the window right (more slack required) and broadens it, but does not raise the peak. The operational reading: \emph{choose $\tau$ comfortably above the median completion time and $\varepsilon \to 0$}; the flooding rate $r$ and deadline $\tau$ are the two knobs.

\paragraph{Adaptive versus oblivious adversaries.}

The measurement above assumes an \emph{oblivious} adversary (i.i.d.\ loss, no protocol knowledge). A \emph{content-observing} adversary changes the picture qualitatively. Consider one that drops nothing---every packet is eventually delivered, so the channel remains fair-lossy---but reads each packet's type off the wire and schedules Alice's triple proofs to arrive at Bob \emph{after} his dawn. It needs no forgery and violates no fair-lossy guarantee; it exploits only the ability to distinguish a $T$-packet from a $C$-packet in flight. On the same harness this adversary produces asymmetric outcomes in $100\%$ of completable runs at $0\%$ base loss and $71.7\%$ at $50\%$ (the remainder both-abort). The knot's authenticity held completely---no artifact was forged---but its \emph{observability} was compromised.

\paragraph{The indistinguishability precondition.}

The adaptive adversary's single capability is packet-type discrimination. Encrypt every packet under a session key, pad all proof levels to a uniform size, and flood at a constant rate from $t_0$, and the wire carries an undifferentiated stream of identical ciphertext blobs: the type-discrimination capability is removed and the adversary is demoted from adaptive to oblivious. This is a cryptographic reduction rather than an assumption---indistinguishability forces obliviousness, and oblivious adversaries are the recognized weaker scheduler class against which randomized-coordination results are proven~\cite{benor1983another}. Under this precondition the relevant bound is the measured oblivious $\varepsilon(\tau)$ of Figure~\ref{fig:eps-tau}, tunable to absurdity via $r$ and $\tau$. The defense is therefore layered, each layer discharging a distinct threat:
\begin{enumerate}
    \item \textbf{Signatures} (authenticity) exclude asymmetric artifact \emph{existence}---Theorem~\ref{thm:safety}, unconditional, Lean-verified.
    \item \textbf{Indistinguishability} (confidentiality + uniform traffic) demotes the scheduler from adaptive to oblivious---the reduction above; a paper-level cryptographic argument, not mechanized in Lean.
    \item \textbf{Flooding and slack} crush the oblivious residue---the $(1-p)^{r\tau}$ right tail, measured.
\end{enumerate}

\paragraph{Scope and caveats.}

Two honest qualifications. First, the $\varepsilon(\tau)$ curve is measured on the Python reference implementation, whose decision rule fires on triple-proof construction; the \emph{form} of the bound is decision-rule-independent---any protocol deciding from local state at a deadline exhibits such a window---but the exact constants are implementation-specific, and the canonical Lean model is terminal-state (it has no clock). Second, the constant-rate, uniform-size precondition of layer~2 is incompatible with adaptive (drip/burst) rate modulation: a state-dependent cadence leaks phase through the encryption and restores adaptivity. Constant-rate and adaptive-flooding are therefore distinct deployment profiles, and the guarantees above hold only for the former.
